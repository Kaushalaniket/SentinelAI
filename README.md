# SentinelAI — AI-Based Intrusion Detection &amp; Cyber Threat Intelligence System

A complete, working full-stack demonstration of a machine-learning network intrusion detection
system (IDS) with a SOC-style operations console.

It is built as a **final-year CSE project**: a real Python backend, a real trained scikit-learn
model, real SQLite persistence, a real React + TypeScript front-end — and an unusually explicit
account of what is *real*, what is *replayed*, and what is *simulated*.

---

## ⚠️ Read this first: what is real and what is not

This project is deliberately honest about its data, because most student IDS demos are not.

| Thing | Status | Evidence |
|---|---|---|
| The machine-learning model | **Real.** Trained with scikit-learn on labelled data. | `backend/data/artifacts/model.joblib` |
| The evaluation metrics | **Real.** Computed on a held-out test split the model never saw. | `backend/data/artifacts/metrics.json` |
| The dataset | **Real.** CIC-IDS2017 — 2,830,743 labelled flows from the Canadian Institute for Cybersecurity. | `backend/data/raw/`, [official page](https://www.unb.ca/cic/datasets/ids-2017.html) |
| Traffic rows tagged `CIC-IDS2017` | **Real records.** Genuine 2017 IPs, ports, protocols and timestamps. | `traffic_records.origin = 'dataset'` |
| Traffic rows tagged `Simulated` | **Synthetic.** Generated by `app/seed.py`. Never scored by the model. | `traffic_records.origin = 'simulated'` |
| Alerts tagged `Model` | **Real inference.** Produced by the trained classifier. | `alerts.origin = 'model'` |
| Alerts tagged `Simulated` | **Demo filler.** Written by the seeder so the console has history. | `alerts.origin = 'simulated'` |
| **Live packet capture** | **Does not exist.** There is no sensor, no pcap, no live feed. | `/api/health` → `"live_capture": false` |

**Nothing on screen is ever presented as a live attack.** A permanent banner on the dashboard and
the sidebar states that no capture is running, and every row and alert carries an origin badge.

## Features

**Eight working pages, each wired to a real endpoint:**

| Page | What it does | Endpoint(s) |
|---|---|---|
| **Dashboard** | KPIs, attack-distribution donut, severity bar chart, hour-of-day histogram, recent alerts, top ports, model status, data-source panel | `GET /api/dashboard/summary` |
| **Live Monitor** | Real-time network flow monitoring with WebSocket streaming. Start/Stop monitoring, SIMULATED and REAL CAPTURE modes. Live charts, searchable/filterable flow table, alert details panel. Clearly marks simulated events. | `GET /api/live/status`, `WS /api/live/ws` |
| **Traffic Analysis** | Paginated flow table with origin/severity/category filters, IP search, detail modal with the full 70-feature vector, buttons to import real CIC-IDS2017 rows or generate simulated rows | `GET /api/traffic`, `POST /api/traffic/simulate`, `POST /api/traffic/load-dataset` |
| **AI Detection** | Three tabs: full evaluation (metrics, per-class table, normalised confusion matrix, baseline comparison, feature importances, training config), CSV classification with drag-and-drop, and batch history | `GET /api/model/metrics`, `POST /api/detect/upload`, `GET /api/detect/batches` |
| **Threat Intelligence** | IP reputation lookup with graceful degradation: live AbuseIPDB/VirusTotal when a key exists, otherwise an offline cached public blocklist — always labelled `live` vs `cached / offline` | `GET /api/intel/lookup`, `/api/intel/status`, `POST /api/intel/refresh` |
| **Alerts** | Severity / status / origin chips, free-text search, sorting, timestamps, incident modal with model probabilities and **historical records for the same endpoint pair**, inline status changes | `GET /api/alerts`, `PATCH /api/alerts/{id}` |
| **Reports** | Summary statistics, four charts, model-eval summary, top source addresses, four CSV exports with optional filters | `GET /api/reports/summary`, `GET /api/reports/export` |
| **Settings** | Three genuinely functional settings, environment/diagnostics panel, API-key status, run instructions | `GET/PUT /api/settings`, `POST /api/settings/reset` |

**Data-integrity features**

- Column validation with a clear rejection message and a list of every missing model feature
- Missing-value and `Infinity` handling via a fitted `SimpleImputer` (median learned at training time)
- Confidence threshold: low-confidence predictions are stored but raise no alert
- `show_simulated_data = false` hides every synthetic row and alert across the whole app
- Loading states, empty states, error states, a global React error boundary, and FastAPI
  request validation on every input

## Quick start (for beginners)

You need **Python 3.10+** and **Node 18+**.

### 1 · Clone and enter the project

```bash
cd sentinelai
```

### 2 · Set up the Python backend

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

#### Windows: Npcap/Scapy requirements (for Real Packet Capture)

For **Real Capture Mode** on Windows:

1. **Install Npcap** - Download from [https://npcap.com/#download](https://npcap.com/#download)
   - During installation, check "Install Npcap in WinPcap API-compatible Mode" (recommended)
   - For live capture you may need to run as Administrator

2. **Install Scapy** (included in requirements.txt):
   ```bash
   pip install scapy
   ```

3. **Run as Administrator** when starting the backend for real packet capture
4. **Check permissions**: The Live Monitor will show interface status and permission requirements

> **Note:** Do not disable Windows security protections. Use Npcap from the official source only.
> In most environments without admin privileges/Npcap, the system safely falls back to **SIMULATED** mode.

### 3 · Download the dataset (2 files, ~520 MB total)

```bash
python -m scripts.download_dataset
```

If you are offline, place the archives yourself at:

- `backend/data/raw/MachineLearningCSV.zip`
- `backend/data/raw/GeneratedLabelledFlows.zip`

### 4 · Build the demo CSVs and train the model

```bash
python -m scripts.generate_samples   # writes 3 CSVs into data/samples/
python -m app.ml.dataset             # ~1 min  → data/artifacts/train_sample.parquet
python -m app.ml.train               # ~90 s   → model.joblib + metrics.json
```

> **A pre-trained model is already included** in `backend/data/artifacts/`, so you can skip this
> step and go straight to running the server. Re-run it only if you want to reproduce the
> training yourself.

### 5 · Start the API

```bash
uvicorn app.main:app --reload --port 8000
```

On first start the API seeds itself in the background: ~250 simulated rows, 530 real CIC-IDS2017
rows, 16 labelled demo alerts, then runs the model over the real rows to create model-generated
alerts. Watch progress at <http://127.0.0.1:8000/api/health>.

### 6 · Start the front-end (new terminal)

```bash
cd ../frontend
npm install
npm run dev
```

Open **<http://localhost:3000>**. Vite proxies `/api` to port 8000, so everything works from one
origin.

### 7 · Production-style single process (optional)

```bash
cd frontend && npm run build         # emits frontend/dist
cd ../backend && uvicorn app.main:app --port 8000
```

FastAPI detects `frontend/dist` and serves the SPA **and** the API from port 8000.

## How the machine-learning pipeline works

**1 · Ingest.** `app/ml/dataset.py` streams the 8 CSVs inside `MachineLearningCSV.zip` one at a
time (peak memory ≈ 220 MB), so a 3.8 GB laptop can handle a 885 MB dataset.

**2 · Normalise labels.** `app/ml/labels.py` lower-cases and strips punctuation from each raw
label, then groups CIC-IDS2017's 15 labels into 9 triage categories — the four DoS variants become
`dos`, the three web attacks become `webattack`, and so on. The mapping is a literal dictionary,
not a heuristic.

**3 · Down-sample honestly.** Rare classes are kept **in full**; common classes are capped:

| Category | Kept | Available in dataset |
|---|---|---|
| benign | 90,000 | 2,273,097 |
| ddos | 60,000 | 128,027 |
| portscan | 60,000 | 158,930 |
| dos | 60,000 | 252,661 |
| bruteforce | 13,835 | 13,835 (all) |
| webattack | 2,180 | 2,180 (all) |
| bot | 1,966 | 1,966 (all) |
| infiltration | 36 | 36 (all) |
| heartbleed | 11 | 11 (all) |

Benign traffic additionally gets a **per-file cap of 12,000** so it is spread across all eight
capture days instead of being taken from the first file read.

**4 · Clean.** `+inf`/`-inf` → `NaN`, every column coerced to `float32`, constant columns dropped
(10 of the CICFlowMeter bulk-average columns are all-zero). Result: 70 usable features.

**5 · Train.** `app/ml/train.py` builds one `Pipeline`:

```python
SimpleImputer(strategy="median", keep_empty_features=True)
StandardScaler()
RandomForestClassifier(n_estimators=128, max_depth=18, max_leaf_nodes=1024,
                       min_samples_leaf=2, max_features="sqrt",
                       class_weight="balanced_subsample", random_state=42)
```

`class_weight="balanced_subsample"` partially compensates for the 90:1 benign/Heartbleed
imbalance. A majority-class dummy classifier and a multinomial logistic regression are trained on
the **same split** so the headline accuracy has something to be compared against.

**6 · Evaluate.** Stratified 80/20 split. Accuracy, balanced accuracy, macro/weighted
precision·recall·F1, a full per-class report and a confusion matrix are all computed from
`y_test` — data the model never fitted on — then written to `metrics.json`.

**7 · Serve.** `app/ml/predictor.py` loads the pipeline once (lazily, thread-safe), re-indexes any
input frame onto the training feature list, and returns `{category, confidence, probabilities}`
per row.

**8 · Classify uploads.** `POST /api/detect/upload` parses the CSV, strips header whitespace,
de-duplicates columns, reports which model features matched / were missing / were ignored, imputes
the gaps, scores every row, stores the results, and raises alerts only above the confidence
threshold.

## Limitations &amp; future work

**Honest limitations**

1. **No live capture.** There is no packet sensor; adding one would mean a CICFlowMeter/Zeek
   collector feeding the same 70-feature vector.
2. **Dataset-based evaluation.** The model was validated on CIC-IDS2017's own test split, not on
   traffic from a different network. Cross-dataset generalisation is the classic IDS weakness and
   is not claimed here.
3. **Two very rare classes.** Heartbleed (11 rows) and Infiltration (36 rows) cannot be evaluated
   meaningfully.
4. **Simulated rows have no feature vector.** By design they are never scored, so they can never
   produce a fake detection — but that also means the synthetic feed is display-only.
5. **Single node.** No authentication, no multi-tenancy, no horizontal scale.

**Reasonable extensions**

- Live capture via CICFlowMeter → Kafka → the existing `/api/detect` scoring path
- Cross-dataset validation (train on CIC-IDS2017, test on CIC-IDS2020 / UNSW-NB15)
- SHAP explanations instead of impurity-based feature importance
- Alert correlation rules and a MITRE ATT&amp;CK mapping
- Sign-in with Freebuff and D1 storage if you deploy it on Sites

### Defects fixed in this pass

- `LiveGauge` parsed `Color.toString()` with `android.graphics.Color.parseColor`, which throws
  and would have crashed the Dashboard and Live Monitor on open. It now uses a safe parser.
- The chart series in `TunnelState` were never populated; every sparkline and waveline was
  blank. Samples are now taken on the 5 s tick, and the UI normalises counters to 0–100.

### Firewall and monitoring scope (unchanged, honest)

Protection mode routes only DNS and the destinations covered by your block rules, so the tablet
keeps normal internet and a block rule really drops matching packets. Full 70-feature flow
capture only happens in a bounded capture session, which pauses internet for that window because
a non-root VPN cannot re-inject TCP without a userspace TCP/IP stack. Nothing is simulated:
counters are incremented where the work happens, and unclassified flows stay unclassified.

## Adaptive layout for every screen size (v1.1.0)

Version 1.1.0 replaces the tablet-first layout with one built from Material 3 window size
classes. A single arm64-v8a APK now serves 5–6" phones, large phones, foldables, 7–8" tablets and
10–13" tablets including the Lenovo Idea Tab Pro, in portrait and landscape.

### Width size classes

| Class | Width | Typical devices | Navigation | Content |
|---|---|---|---|---|
| Compact | 0–599 dp | 5–6" phones, folded flip covers | Bottom bar (Dashboard, Live, Traffic, Alerts) + "More" sheet with the other five modules | One column, 14 dp padding, 140 dp minimum tile width |
| Medium | 600–839 dp | Large phones in landscape, 7–8" tablets, unfolded foldables | Scrollable icon-and-label rail, 92 dp | Two readable panes when both fit, 156 dp tiles |
| Expanded | 840 dp+ | 10–13" tablets, Idea Tab Pro | Persistent 220–248 dp sidebar with module list and live tunnel status | Two-to-five columns, 22 dp padding, 168–172 dp tiles, content capped at 1240 dp |

`calculateWindowSizeClass(activity)` supplies the class, so rotation, split-screen, desktop
windowing and foldable unfold/refold all flow through one value; the activity already declares
`configChanges` for orientation, so rotating never restarts the tunnel.

### What adapts

- **Navigation** — bar → rail → sidebar, as above. Every item keeps a 44–56 dp touch target, and
  the rail/sidebar scroll, so all nine modules stay reachable on a landscape phone 360 dp tall.
- **Spacing** — 10/12/14 dp gaps, 14/18/22 dp screen padding, 14/16/18 dp card padding.
- **Typography** — body and headline sizes grow in sp with the size class (body small 13 → 14 sp,
  headline medium 30 → 32 sp) and still respect the user's font-scale setting.
- **Grids** — stat tiles, tunnel counters and report gauges lay out from the measured container
  width. `columnsFor()` guarantees `columns × minTileWidth + gaps` fits, which stops cards
  overflowing on a 320 dp phone.
- **Charts** — plot heights 68/80/96 dp by class; strokes, dots and bar corners scale with
  density; every chart fills its pane instead of a fixed 140 dp width.
- **Two-pane panels** — dashboard, live monitor and reports pair related panels once two 340 dp
  panes fit, and stack on phones.
- **No clipping** — label/value rows stack under 320 dp, long IPs and domains ellipsise instead
  of pushing badges off-screen, fixed-width labels became weights, stat values may wrap to two
  lines, and the status strip moves its counters to a second line when narrow.
- **Edge-to-edge** — `enableEdgeToEdge()` plus `safeDrawingPadding()` keeps content clear of the
  status bar, navigation bar and camera cutouts, which targetSdk 35 requires.
- **Copy** — user-facing text says "device" rather than "tablet".
